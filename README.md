# Спринт 2 Система обратных аукционов

Рабочая серверная часть (backend) учебного проекта: Django 5.2, Django REST Framework, SQLite для локальной демонстрации и PostgreSQL для командного стенда. Python 3.12 рекомендуется. Интерфейс пользователя в комплект не входит.

Начните с `docs/SPRINT_2.md`: там распределение работы на 7 человек, вариант для 6, критерии приёмки и изменения первого ТЗ. Контракт интерфейса — `docs/API.md`. Честный статус поставки — `docs/DELIVERY.md`.

## Локальный запуск

Из каталога, в котором находится manage.py:

```bash
python -m venv .venv
# Linux / macOS
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py test -v 2
python manage.py runserver
```

В другом терминале с тем же окружением запустите обработчик:

```bash
python manage.py close_auctions --loop
```

Проверка: http://127.0.0.1:8000/api/auth/csrf/ возвращает токен; без входа каталог отвечает 403. Команда `seed_demo` создаёт owner, bidder1, bidder2, bidder3, moderator; пароль новых аккаунтов `Demo-only-2026!`. Все адреса фиктивные, почта подтверждена только для демонстрации. Команда повторно не сбрасывает пароли и не создаёт дубликаты. У начальной задачи торги заканчиваются через 15 минут после создания; при повторном запуске срок не продлевается. Для новой демонстрации создайте задачу через API.

## Демонстрация без клиентского приложения

При работающем сервере:

```bash
python scripts/demo.py
```

Сценарий входит пятью аккаунтами, создаёт задачу на 12 секунд, отправляет на модерацию, публикует, принимает ставки 700, 900 и 1100 рублей и проверяет приватность. Затем выполните `python manage.py close_auctions` (либо держите запущенным `--loop`) и откройте выданный адрес результата через авторизованный клиент. Ожидается bidder1 и цена 900 рублей. Скрипт сам не закрывает торги и не подменяет серверные сроки.

## PostgreSQL и контейнеры

Скопируйте `.env.example` в `.env`, замените секреты, затем:

```bash
docker compose up --build -d
# В другом терминале
# Все проверки, включая два конкурентных теста PostgreSQL
docker compose exec web python manage.py test -v 2
docker compose exec web python manage.py seed_demo
```

Стенд доступен на 127.0.0.1:8000. Compose запускает миграции, сервер разработки и отдельный обработчик закрытия. Это учебный стенд, не промышленная публикация. Не запускайте несколько контейнеров с SQLite. При использовании PostgreSQL вручную задайте POSTGRES_HOST, POSTGRES_PORT, POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD. Для тестов у пользователя БД должно быть право CREATE DATABASE.

Внешние запросы к закрытию и ручное назначение победителя отсутствуют. Обработчик можно безопасно повторять. Запись ставки и закрытие используют одну блокировку строки аукциона в транзакции. SQLite не проверяет блокировки строк: конкурентные тесты на нём намеренно пропускаются. Их нужно прогнать на PostgreSQL перед командной приёмкой.

При DEBUG=0 требуются собственный SECRET_KEY, HTTPS и ALLOWED_HOSTS; cookie становятся Secure. Защита CSRF включена, включая вход; клиент и API предполагаются на одном источнике (same origin). Не отключайте её для интеграции React: используйте проксирование `/api`.
