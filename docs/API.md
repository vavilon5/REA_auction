# Контракт API спринта 2

Базовый путь `/api/`. Тела и ответы — JSON. Время — ISO 8601 с часовым поясом, например `2026-11-05T12:00:00+03:00`; хранение в UTC. Суммы — целые копейки. Каталог доступен только активному пользователю с email_verified=true. Один пользователь совмещает заказчика и исполнителя. Официальная идентификация для локального входа — username, не email; переход на вход по email и регистрация отложены.

## Авторизация

1. `GET /api/auth/csrf/` без входа возвращает `{"csrfToken":"..."}` и устанавливает cookie.
2. `POST /api/auth/login/` с `{"username":"owner","password":"Demo-only-2026!"}`. Передать заголовок `X-CSRFToken` из шага 1 и cookie. Ответ 200: id, username и НОВЫЙ csrfToken, поскольку при входе токен меняется.
3. Для изменяющих запросов передавать новый `X-CSRFToken`, сессионные и CSRF cookie. В браузере использовать один источник с сервером, `credentials: "same-origin"`.
4. `GET /api/auth/me/` → id, username, can_moderate. `POST /api/auth/logout/` с CSRF → 204 и отзыв сессии.

Защита CSRF применяется также к входу. Возвращённый API токен предназначен для заголовка, cookie сессии HttpOnly. Нет JWT и ручного хранения пароля в браузере. Лимит попыток входа в этой учебной поставке не реализован, стенд следует держать локальным.

## Маршруты

| Метод и путь | Кто | Результат |
|---|---|---|
| GET /categories/ | Допущенный участник | Справочник категорий, 200 |
| GET /auctions/ | Допущенный участник | Доступные аукционы, пагинация |
| POST /auctions/ | Допущенный участник | Собственный черновик, 201 |
| GET /auctions/{id}/ | Имеющий доступ к объекту | Карточка, 200 |
| PATCH /auctions/{id}/ | Владелец draft или rejected | Изменённый черновик, 200 |
| POST /auctions/{id}/submit/ | Владелец draft или rejected | review, 200 |
| POST /auctions/{id}/approve/ | Независимый модератор, review | open, 200 |
| POST /auctions/{id}/reject/ | Независимый модератор, review | rejected, 200 |
| GET /auctions/{id}/bids/ | Имеющий доступ к объекту | Только собственные ставки, массив |
| POST /auctions/{id}/bids/ | Допущенный исполнитель чужой open задачи до срока | Своя ставка, 201; повтор 200 |

Пути в таблице прибавляются к `/api`. DELETE, PUT, изменение ставок, внешний метод закрытия и ручной выбор победителя отсутствуют; недоступный метод даёт 405. Категории создаются seed_demo или командой Django, отдельного API изменения нет.

Для каталога: `?mine=1`, `?status=open`, `?category=1`, `?search=алгоритм`, `?page=2`. Фильтры объединяются. По умолчанию возвращаются все доступные записи: свои в любых статусах, чужие open/closed, для модератора дополнительно review. Для публичного раздела торгов клиент обязан передать `status=open`. Размер страницы 20. Ответ: `{"count":1,"next":null,"previous":null,"results":[...]}`. Собственный paused видит заказчик, отдельной очереди paused для модератора в этом спринте нет.

## Создание задачи

```json
{
  "category": 1,
  "title": "Консультация по алгоритмам",
  "description": "Объяснить бинарный поиск и разобрать учебные примеры.",
  "budget_kopecks": 150000,
  "ends_at": "2026-11-05T12:00:00+03:00",
  "due_at": "2026-11-07T12:00:00+03:00"
}
```

Укажите фактические будущие даты. Заголовок 5–150 символов, описание 20–5000, бюджет 100–10^12 копеек; срок выполнения строго позже торгов. PATCH принимает часть этих полей, ограничения сохраняются. Входные служебные поля status, owner_id, winner_id и payment_kopecks не управляют результатом — они только для чтения. Клиент не должен передавать их при записи.

Отправка на модерацию: `{}`. Публикация и отклонение: `{"reason":"Допустимая учебная консультация"}` — непустая причина до 2000 символов. Публикация возможна только из review; approve повторно даёт 409. Публиковать собственную задачу нельзя даже с правами модератора.

## Ставка и повтор

```http
POST /api/auctions/1/bids/
Content-Type: application/json
X-CSRFToken: <актуальный токен>
Idempotency-Key: <случайный UUID запроса>

{"amount_kopecks":70000}
```

Первая успешная запись даёт 201:

```json
{"id":1,"auction_id":1,"amount_kopecks":70000,"created_at":"2026-11-05T08:00:00Z"}
```

Точный повтор → 200 и та же запись. Этот повтор работает и после закрытия, если пользователь сохранил допуск и доступ к карточке. С тем же ключом и другой суммой → 409. Новый ключ после принятой ставки → 409. Ключ обязателен, непустой, до 80 символов, действует в области пользователя и одного аукциона. При сетевой ошибке повторять исходное тело и ключ; после обновления страницы сначала GET собственных ставок. Ключ не требуется для остальных методов, их повторяемость не гарантируется.

GET bids возвращает `[своя ставка]` либо `[]`. Чужие суммы, число ставок и текущий минимум не возвращаются. Сервер не добавляет шаг понижения и не сравнивает ставку с конкурентом. Валидация положительности и бюджета обязательна. Неположительное/дробное значение или превышение бюджета → 400; собственная задача → 403; не open или истёкший срок → 409.

## Карточка и итог

```json
{
  "id": 1,
  "owner_id": 1,
  "category": 1,
  "title": "Консультация по алгоритмам",
  "description": "Объяснить бинарный поиск и разобрать учебные примеры.",
  "budget_kopecks": 150000,
  "ends_at": "2026-11-05T09:00:00Z",
  "due_at": "2026-11-07T09:00:00Z",
  "status": "closed",
  "moderation_reason": "Допустимая учебная консультация",
  "winner_id": 2,
  "payment_kopecks": 90000,
  "closed_at": "2026-11-05T09:00:04Z"
}
```

До closed winner_id и payment_kopecks равны null. При закрытии без ставок оба тоже null, но closed_at заполнен. При paused результат не определён. Вторая цена — payment_kopecks, её нельзя подменять собственной ставкой. Контакты, адреса почты и личности проигравших не публикуются. Имена победителей в этом спринте не разрешаются отдельным endpoint; достаточно идентификатора. Карточку опрашивать раз в 5 секунд; после локального истечения срока показывать «Ожидаем завершения сервером», пока статус open.

## Ошибки

| Код | Значение | Действие клиента |
|---|---|---|
| 400 | Невалидные данные или нет ключа | Показать ошибку поля, не повторять автоматически |
| 403 | Нет сессии, допуска, права или неверен CSRF | Предложить вход либо обновление токена; не считать запись успешной |
| 404 | Объект отсутствует или его нельзя видеть | Показать недоступность без раскрытия черновика |
| 409 | Состояние изменилось, дубль ставки или конфликт ключа | Обновить карточку и собственную ставку |
| 405 | Метод не поддерживается | Исправить клиент |

Типовое тело: `{"detail":"Приём ставок закрыт"}` либо словарь ошибок полей `{"amount_kopecks":["..."]}`. CSRF-ошибка входа может быть HTML-ответом Django: клиент должен проверить Content-Type перед JSON-разбором и показать безопасное сообщение. Конкретные тексты ошибок не являются машинными кодами, ориентируйтесь на HTTP-статус и поля.

У API нет публичного доступа к событиям аудита, произвольным пользователям или изменению прав. Группа «Модераторы» получает Django permission `auction.moderate_auction`; служебное право хранится отдельной связью, не приходит из формы профиля. Панель администратора в комплекте не подключена, назначать права через API нельзя.
